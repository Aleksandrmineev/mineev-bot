# karriere-telegram-parser

Личный Telegram-бот, который следит за твоими сохранёнными поисками вакансий
на [karriere.at](https://www.karriere.at) и присылает новые подходящие
вакансии быстрее, чем стандартный ежедневный Job-Alarm.

## ⚠️ Прежде чем запускать

Этот бот работает только с **публичными страницами поиска** karriere.at,
через обычные HTTP-запросы (без headless-браузера, без обхода CAPTCHA,
Cloudflare, rate limits или авторизации). Он не использует твой аккаунт
karriere.at и не собирает персональные данные.

Тем не менее: **проверь актуальные Nutzungsbedingungen (условия
использования) karriere.at** и при необходимости получи разрешение на
автоматизированный доступ, прежде чем запускать бота на постоянной основе.
Это твоя ответственность как оператора бота, не бота как программы.

По умолчанию проверка выполняется не чаще одного раза в 15 минут
(`POLL_INTERVAL_SECONDS`, минимум принудительно ограничен 900 секундами
даже если задать меньше).

## Возможности

- Несколько сохранённых поисков karriere.at на один Telegram-чат.
- Управление через команды бота или через локальную веб-панель (без
  правки кода).
- Первая страница результатов всегда запрашивается с сортировкой по дате
  публикации (`sort=date` добавляется автоматически при `/add`) — без
  этого порядок на сайте не хронологический (спонсорские/"Smart
  Bewerben" вакансии могут стоять выше новых), и новая вакансия могла бы
  просто не попасть в первые 15 результатов.
- Для каждой по-настоящему новой вакансии бот дополнительно загружает её
  страницу (один запрос на вакансию, не на всю выдачу) и подмешивает
  описание к фильтрам по ключевым словам — без этого `include_keywords`/
  `exclude_keywords` видели бы только заголовок.
- Локальные фильтры: обязательные/исключающие слова (по заголовку и
  описанию), минимальная зарплата, разрешённые города, только Homeoffice,
  тип занятости.
- Дедупликация: вакансия не отправляется повторно (по ID, а если ID не
  извлёкся — по нормализованному URL). Каждая новая вакансия оценивается
  фильтрами один раз; если позже смягчить фильтры, уже отсеянные ранее
  вакансии повторно не всплывут (только новые).
- Устойчивость: таймауты, ограниченные повторы с экспоненциальной задержкой
  только для временных ошибок, корректная обработка HTTP 429/403 без
  повторных попыток задавить сайт, поштучная обработка вакансий (одна
  битая вакансия/страница не роняет весь цикл проверки), retry для
  неудачной отправки в Telegram (вакансия не теряется, даже если к моменту
  повторной попытки она уже пропала со страницы поиска — полные данные
  сохраняются в базе).

## Требования

- Python 3.12+
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather)

## Установка и запуск

```bash
cp .env.example .env
cp telegram.env.example telegram.env
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
playwright install chromium
pytest
python -m src.main
```

### Настройка

Конфигурация разнесена по двум файлам:

- **`telegram.env`** — только Telegram-креды, `TELEGRAM_BOT_TOKEN` и
  `TELEGRAM_CHAT_ID`. Больше в этом файле ничего нет — удобно открыть и
  сразу увидеть, что вписывать.
- **`.env`** — всё остальное (`POLL_INTERVAL_SECONDS`, `DATABASE_PATH`,
  `USER_AGENT`, задержки и повторы), можно оставить по умолчанию, см.
  `.env.example`.

Заполнение `telegram.env`:

1. Напиши [@BotFather](https://t.me/BotFather) в Telegram, создай бота
   командой `/newbot`, скопируй выданный токен в `TELEGRAM_BOT_TOKEN`.
2. Оставь `TELEGRAM_CHAT_ID` пустым, запусти бота (`python -m src.main`) и
   отправь ему `/start` — он ответит твоим chat id.
3. Впиши этот chat id в `TELEGRAM_CHAT_ID` в `telegram.env` и перезапусти
   бота. С этого момента бот принимает команды только из этого чата.

Оба файла — `.env` и `telegram.env` — в `.gitignore`, в репозиторий не
попадают.

## Управление в Telegram

После `/start` бот показывает постоянную клавиатуру с кнопками — это
основной способ управления, ничего печатать не нужно:

- **📋 Мои поиски** — список сохранённых поисков, у каждого кнопка
  «🗑 Удалить» прямо под ним.
- **➕ Добавить поиск** — бот попросит прислать ссылку на поиск karriere.at
  (или нажать «❌ Отмена»).
- **🕘 Последние вакансии** — до 5 последних реально отправленных вакансий.
  Самый быстрый способ убедиться, что бот работает, не дожидаясь новой
  подходящей вакансии.
- **🔍 Проверить сейчас** — не ждать таймера, проверить сразу.
- **⏸ Пауза / ▶️ Возобновить** — один переключатель, подпись меняется в
  зависимости от текущего состояния.
- **⚙️ Статус** — активна/на паузе, число поисков, время последней
  проверки, интервал.

Команды тоже работают, если так привычнее:

| Команда | Что делает |
|---|---|
| `/start` | Показывает клавиатуру; на первом запуске (пока `TELEGRAM_CHAT_ID` не задан) — chat id |
| `/add <url>` | Добавить URL поиска karriere.at, например `/add https://www.karriere.at/jobs?keywords=python&locations=Graz`. Без URL — тот же диалог, что и по кнопке |
| `/list` | Показать активные поиски с их id |
| `/remove <id>` | Удалить поиск по id из `/list` |
| `/check` | Выполнить проверку немедленно, не дожидаясь таймера |
| `/pause` / `/resume` | Остановить / возобновить автоматические проверки |
| `/status` | Статус: пауза/активна, число поисков, время последней проверки |

## Веб-интерфейс

Локальная панель для управления поисками и предпросмотра разбора — не
требует настроенного Telegram, читает и пишет ту же SQLite-базу
(`DATABASE_PATH`), что и бот, так что добавленное в веб-панели видно и в
`/list`, и наоборот.

```bash
pip install -e '.[web]'
uvicorn src.web.app:app --reload --port 8000
```

Открой `http://127.0.0.1:8000` — там:

- **Дашборд** — статус автопроверки (пауза/активна), настроен ли Telegram,
  список сохранённых поисков с добавлением/удалением, текущие фильтры из
  `config/filters.example.yaml` (или твоего `FILTERS_CONFIG_PATH`).
  Добавлять поиск можно двумя способами:
  - **Быстрый поиск** — отдельные поля «Ключевые слова», «Локация»,
    «Радиус, км» и чекбокс «только Homeoffice»; ссылка на karriere.at
    собирается автоматически (`sort=date` добавляется как обычно). Поле
    локации — обычный текст: город, район (Bezirk) или земля
    (Bundesland), например `Graz`, `Murtal` или `Steiermark` — karriere.at
    сам разбирает это так же, как при поиске на самом сайте, поэтому
    отдельный список регионов не нужен и не встроен: без явного `radius`
    поиск идёт точно по указанной локации, без расширения зоны.
  - **Готовая ссылка** (свёрнутый блок ниже) — вставить URL, скопированный
    прямо с karriere.at, если нужны фильтры, которых нет в быстрой форме
    (например, конкретные Berufsfelder).
- **Предпросмотр поиска** (`/preview`) — вставляешь ссылку на поиск
  karriere.at, бот делает один запрос (с автоматическим `sort=date`),
  парсит и показывает таблицу вакансий с пометкой, прошла бы вакансия
  текущие фильтры или нет. Фильтрация здесь только по заголовку —
  описание вакансии для предпросмотра не подгружается (иначе повторные
  клики «Проверить» кратно увеличивали бы число запросов к сайту).

Панель без аутентификации и рассчитана только на `localhost` — не
выставляй её наружу.

## Фильтры

Локальные фильтры применяются после получения и разбора вакансий — они
ничего не меняют в запросах к сайту. Настраиваются файлом
`config/filters.example.yaml` (скопируй в `config/filters.yaml` и
отредактируй, либо укажи свой путь через `FILTERS_CONFIG_PATH`):

```yaml
include_keywords: []      # обязательные слова в названии/описании
exclude_keywords: []      # исключающие слова
min_salary: null          # минимальная зарплата в EUR/мес (годовая делится на 12)
allowed_locations: []     # разрешённые города (подстрока, без учёта регистра)
homeoffice_only: false    # только вакансии с пометкой Homeoffice
employment_types: []      # например ["Vollzeit"]
```

Личные критерии в код не зашиты — правь только этот файл.

## Данные вакансии

Извлекаются: ID, название, компания, место работы, тип занятости,
зарплата (как есть на сайте), признак Homeoffice, дата публикации (как
относительный текст с сайта, например «vor 2 Tagen», плюс наилучшее
приближение к календарной дате), URL, время обнаружения ботом.

**Описание вакансии** подгружается отдельным запросом, но только для
вакансий, которых ещё не было в базе (не для всех 15 на странице выдачи
каждый цикл) — используется исключительно для фильтров по ключевым
словам и **не показывается** в самом Telegram-сообщении: реальный текст
вакансии на karriere.at в основном дублирует уже показанные поля
(тип занятости, зарплата, размер компании и т.д.) вперемешку с версткой
конкретного работодателя, и в сыром виде в уведомлении выглядит просто
шумом. Если страницу вакансии не удалось загрузить (сайт временно
недоступен, 429/403), фильтрация по ключевым словам в этот раз пройдёт
только по заголовку — вакансия не теряется, просто фильтр менее точен
для неё однократно.

## AMS

AMS можно подключить к тому же Telegram-боту без использования официального
API. В этом режиме Playwright в фоне открывает публичную форму `alle jobs`,
заполняет сохранённые параметры поиска и читает отрендеренные результаты.
Логин, MeinAMS, пользовательские cookies и обход CAPTCHA не используются.

AMS выключен по умолчанию. Для включения установи Chromium командой
`playwright install chromium`, добавь в `.env` `ENABLE_AMS=true` и перезапусти
бота. AMS-поиск можно добавить через локальную веб-панель или командой:

```text
/addams IT Support | Leoben | 20
```

Параметры AMS хранятся отдельно от параметров karriere.at, поэтому разные
формы поиска не смешиваются. Если AMS изменит интерфейс, его адаптер и тесты
можно обновить отдельно, не затрагивая karriere.at.

База данных сохраняется в `./data`, конфиг фильтров монтируется из
`./config` (только для чтения).

## Тесты

```bash
pytest
```

Все тесты работают на сохранённой HTML-фикстуре (`tests/fixtures/`) и не
обращаются к реальному karriere.at. Дополнительная ручная проверка на
живом сайте — отдельным скриптом, не запускается тестами:

```bash
python scripts/live_check.py "https://www.karriere.at/jobs?keywords=python&locations=Graz"
```

Делает один запрос к странице поиска (с `sort=date`) и один — к странице
первой найденной вакансии, с той же задержкой между запросами, что и в
самом боте. Печатает результат, ничего не пишет в базу и не отправляет в
Telegram.

## Очистка старых записей

Записи дедупликации старше `RECORD_RETENTION_DAYS` (по умолчанию 90 дней)
можно удалить вручную:

```bash
python -m src.main --cleanup
```

## Известные ограничения

- Разбирается только первая страница результатов поиска (обычно ~15
  вакансий), но с принудительной сортировкой по дате публикации —
  благодаря этому пропустить новую вакансию можно только если по
  конкретному сохранённому поиску появляется больше 15 новых вакансий за
  один интервал проверки (по умолчанию 15 минут), что маловероятно для
  осмысленно сузженного личного поиска. Настоящей постраничной загрузки
  (страница 2 и далее) нет и не планируется: у karriere.at это не обычная
  публичная HTML-страница с URL-параметром, а JS-подгрузка через кнопку
  «Weitere Jobs anzeigen» — воспроизводить её в обход браузера означало бы
  подбирать недокументированный внутренний запрос, а не читать публичную
  страницу, поэтому сознательно не реализовано.
- Дата публикации на странице поиска — только относительная («сегодня»,
  «vor N Tagen»); календарная дата — наилучшее приближение на момент
  проверки, не гарантированно точная до дня для «vor N Wochen/Monaten».
- Зарплата берётся как есть с сайта; для фильтра `min_salary` годовая
  сумма делится на 12 для сравнения с месячным порогом — это объявленное
  правило пересчёта, а не факт с сайта.
- Описание вакансии подгружается только один раз, при первом обнаружении
  вакансии, и используется только для фильтров — см. раздел «Данные
  вакансии» выше про компромисс с повторной оценкой после смягчения
  фильтров.
- В худшем случае (первый запуск, поиск с большим числом сразу новых
  вакансий) один цикл проверки может сделать до `1 + N` запросов, где N —
  число новых вакансий на странице (обычно 0–3 в спокойном режиме, до 15
  на самом первом запуске), каждый с задержкой `REQUEST_DELAY_SECONDS`
  между ними — это по-прежнему один цикл раз в 15+ минут, не постоянный
  поток запросов.
- Структура HTML karriere.at может измениться в любой момент; если парсер
  перестанет находить вакансии или описания, это будет видно по
  логам/пустым результатам — обход защит вместо починки парсера не
  предусмотрен и не будет добавлен.
- Бот — однопользовательский: один `TELEGRAM_CHAT_ID` на инстанс.
- Веб-панель и бот пишут в один и тот же файл SQLite — это нормально для
  личного использования одним человеком с невысокой частотой запросов, но
  панель без аутентификации и не рассчитана на то, чтобы быть доступной
  откуда-то кроме `localhost`.
